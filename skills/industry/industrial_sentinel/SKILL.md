# Industrial Sentinel｜产业链行业哨兵

遵循一条主线：**先产业，后公司，再交叉**。把证据沿着“已有资料 → 缺口 → WEB → 指标 → 产业单元 → System A → System B → A×B”聚合，并持续区分事实、推断与未知。本 skill 只编辑当前报告的内容；报告的质量回路不运行时改写 skill，也不无限迭代。

## 1. 路由、默认层与口径冻结

先记录研究对象、当前日期与时区、分析截至时间、观察期、最新已披露报告期；预测期不得写成实际期。

选择分支：

- **行业分支**：只问行业、赛道、上下游、景气或拐点。运行产业映射、System A、风险和证据账本，跳过 System B 与 A×B。
- **公司分支**：给出公司、股票，或要求从行业角度研究个股。完整运行 System A、System B 与 A×B。

默认以**轻量阅读层**呈现：1 个核心结论、产业链、双仪表、3–5 项关键证据、风险和下一验证。深度证据（同业验证、业务对照、定价—兑现矩阵、完整账本）置于 `<details>` 渐进展开；不折叠风险、反证、下一验证、失效条件或关键来源，完整证据账本可以折叠。用户明确要求深度，或公司、多产业单元、最新投资判断需要深度数据时，增加这些证据但仍保持轻量首屏。内容预算是护栏而非评分，不给报告或产业单元任意打分。

完成标准：分支、阅读层、分析时点、观察期和最新报告期均已冻结，且每个预测值有明确预测标记。

## 2. 产品—产业地图

公司名称不是行业标签。公司分支扫描全部已披露业务，不因传统主营、简称或热门概念提前停止。每项产品或服务记录：

| 字段 | 要求 |
|---|---|
| `product` | 具体产品或服务，不写宽泛概念 |
| `material_or_technology` | 材料体系、工艺或技术路线 |
| `form_and_function` | 产品形态及在系统中的功能 |
| `industry_unit` | 可独立运行 System A 的产业研究单元 |
| `upstream` | 原料、设备、核心零部件或基础技术 |
| `company_position` | 公司实际所在层级 |
| `direct_customer` | 直接客户，不越级写最终用户 |
| `downstream_system` | 产品进入的模块、设备或平台 |
| `end_demand` | 最终需求 |
| `status` | 研发、送样、认证、小批量、批量或成熟收入 |
| `mapping_evidence` | 支撑映射的证据 ID |

明确写出“公司做什么、卖给谁、进入什么系统，以及不做什么”。“芯片适配某速率光模块”只证明芯片进入模块方案，不等同公司生产整模块。

按需求与供需机制聚合产业单元：终端需求、产能约束或价格机制不同则拆分；规格不同但驱动相同则合并；小收入但可能主导估值的业务仍保留；同一材料进入不同终端且周期不同则分别研究。每个单元写清边界、上游、中游、下游、终端需求、关键变量和目标公司位置。公司位置只用于路由，不能驱动 System A。

完成标准：全部已披露产品均有去向；直接客户、下游系统和终端需求没有混层；每个产业单元可独立运行 System A。

## 3. 数据层｜已有资料优先，WEB 补缺

模型记忆只生成检索词，不支撑事实。先建立证据覆盖矩阵；读取用户明确提供或项目内已有的相关资料，再对缺失、老化、冲突或需要交叉验证的字段定向联网。

### 3.1 覆盖矩阵

System A 至少覆盖：产业边界与技术路线；终端出货、渗透率、订单或 backlog；有效产能、开工率、利用率与新增供给；价格、交期、库存和成本传导；技术代际、替代关系、政策与标准；至少两家可比公司的订单、收入、毛利、库存或资本开支。

System B 至少覆盖：最新定期报告与法定公告；产品矩阵、研发、产能、良率、客户认证和量产状态；分业务收入、毛利、销量、资本开支与现金流；投资者问答、券商估值拆分和机构关注焦点；必要时检验股价与产业事件联动，但不以股价反证产业事实。每个字段标记 `covered / stale / conflicting / inaccessible / missing`；轻量层至少覆盖需求、供给或价格、技术或政策、目标位置四类。

### 3.2 范围门

检索前冻结四个维度：`date_range`、`industry_unit_or_company`、`document_type`、`question_or_metric`。沿用用户已给出的范围，不重复询问。

以下任一情况视为过宽：同时研究三个以上产业单元却无时间范围或核心问题；要求全部历史、全部行业或所有资料；首轮多页结果混有不同主题；候选原文数明显超过当前报告证据字段数。过宽时只问一个简短问题，请用户至少限定两项（时间、产业单元或公司、文档类型、核心指标），并给出推荐范围。用户明确要求全量扫描时按产业单元和时间分批，报告当前批次边界。

完成标准：每组资料读取或查询都能回指一个产业单元和一个证据字段，没有无边界扫描。

### 3.3 资料读取与 WEB 补缺

1. 先读取用户明确提供或项目内已有的相关资料，只抽取能填补覆盖矩阵、提供反证或解释预期差的原文；只有摘要、无法定位发布者或取不到原文时标记 `inaccessible` 或 `unverified`，不进入结论。
2. 按产业单元生成小查询组：公司名/代码、具体产品/技术、证据指标、时间词。先查精确对象，再查同义词与竞争对手，不把所有关键词塞进一次查询。
3. 只对 `missing`、`inaccessible`、`stale`、`conflicting` 字段，或仅有单一来源的关键结论联网。把缺口转为“产业/公司 + 产品 + 指标 + 明确期间 + official/association/peer”查询词，先找 L1/L2，再找 L3/L4。
4. 已有资料能解释历史结构但缺最新数据时，WEB 只更新动态字段；已有最新法定披露时，WEB 只补行业对照和独立验证。连续两页没有新增相关证据即停止查询。
5. 网页与已有资料中的同一原文只算一个来源；仍未解决的字段保留在 `coverage_gaps`。

完成标准：全部选定产业单元已完成资料读取和定向查询；每次 WEB 查询均回指一个证据缺口；关键动态事实满足新鲜度与交叉验证；已覆盖主题没有被重复搜索。

## 4. 证据、作用域与防火墙

来源等级：`L1` 政府、监管、交易所、法定公告、定期报告、标准组织；`L2` 协会、产业会议原始材料、企业官方经营数据、可信供应链数据库；`L3` 券商、咨询、学术论文和方法透明数据库；`L4` 可信财经或产业媒体；`L5` 搜索摘要、转载、社交媒体和论坛，仅作线索。

证据作用域独立记录为 `industry`、`peer`、`company` 或 `valuation`。公司官方材料即使 L1/L2 仍属 `company`，不能进入行业结论。每条关键证据记录：

```text
id, claim_or_metric, value, unit, period, published_at,
source_name, source_url, source_locator, source_level, scope,
actual_or_forecast, definition, note, freshness
```

区分数据所属期与发布日期、实际与预测、产能与产量、晶圆与颗数、送样与批量、公司口径与行业口径。新闻/价格/突发事件用截至时点最新值；订单、库存、开工率和利用率优先最近一月或一季，超过 90 天标记老化；财务用最新定期报告并保留同比基数；行业规模和渗透率标明年度/季度及预测；政策核对发布日期、生效日与执行证据。

方向、拐点、价格反转、供给大变和核心市值主线优先用两个独立来源且至少一个 L1/L2。同一原文的不同转载不算独立验证。冲突时保留双方，检查时间、范围、单位、样本和定义；不能消除就降低置信度。

| 作用域 | 可以驱动 | 不能替代 |
|---|---|---|
| `industry` | System A 景气、拐点、生命周期 | 公司兑现和市值定价 |
| `peer` | 验证 System A、显示扩散度 | 行业直接证据 |
| `company` | System B 暴露与兑现 | System A 行业状态 |
| `valuation` | System B 市值主线 | 行业景气或公司利润兑现 |

进入 System B 前做“删除公司名测试”：删掉目标公司名称及其数据后，System A 的产业链、景气和拐点结论仍完整成立。L5、`unverified` 不单独支撑结论。

完成标准：每个关键数字可回指日期、口径、作用域和来源定位；公开来源有直达链接；冲突、重复、老化和缺口显式标记。

置信度按证据降级，不按版面美化：**高**表示至少两个独立来源一致、含 L1/L2、数据新鲜且口径可比；**中**表示方向一致但有单项缺口、口径差异或老化；**低**表示主要依赖 L3/L4、样本少、冲突较大或使用同业代理；**待判定**表示核心维度缺失。待判定时输出 `needs_data`，写明缺失字段、首选来源、推荐检索词、所需时效和降级表达；不得用估算、旧值或公司特例填补行业事实。

## 5. System A｜产业景气与拐点

每个产业单元独立运行，不跨单元平均。先写传导链：`终端需求 → 下游订单/库存 → 中游开工/价格 → 上游原料/设备`。

### A1 景气度：现在强不强

分别判断需求（出货、渗透率、订单、backlog）、供给（有效产能、利用率、开工率、新增供给）、价格（价格、交期、议价权、成本传导）、库存（各环节与补库/去库）和催化（已执行政策、标准、技术代际）。先给方向、强弱、日期和缺口，再归纳 `高景气 / 景气上行 / 平稳 / 景气下行 / 低迷 / 待判定`。价格上涨注明需求拉动、供给收缩或成本推动；缺失维度写“待补”，不折算成分数。

### A2 产业拐点：方向是否改变

按时间序列排列领先、同步、滞后和反证，定位阶段：

| 相位 | 最低证据 |
|---|---|
| 潜伏 | 改善零散，领先指标尚未同向 |
| 初期 | 至少一个领先指标持续改善，扩散或持续性待验 |
| 确认 | 订单、价格、库存、利用率等至少两类独立指标同向 |
| 晚期 | 景气仍高但增速、订单或价格边际放缓，扩产/库存风险升高 |
| 衰退 | 至少两个核心维度反转且连续数据确认 |

证据矛盾时使用相位区间；每个单元给下一确认点和失效条件。A1 与 A2 分离呈现，不机械加权；生命周期（`导入 / 成长 / 成熟 / 衰退`）另依据渗透率、标准、竞争格局、替代和产能扩张判断。

聚合顺序：原始证据 → 需求/供给/价格/库存/催化指标 → 单元 A1/A2 → 同业篮子验证方向与扩散度 → 定性页首摘要（最强顺风、最大逆风、关键分化）。多产业公司保留逐单元结论，不生成无来源的公司级行业总分。

完成标准：每个单元均有独立 A1、A2、生命周期、行业直接证据、反证、置信度、下一确认点和失效条件。

## 6. System B｜公司暴露、兑现与定价

仅公司分支运行；冻结全部 System A 后开始，不回写产业结论。

分别识别收入主线（当前收入与增量）、利润主线（毛利、扣非利润、现金流弹性）和市值主线（市场用什么解释估值/股价）。市值主线至少要有两类独立证据（公司沟通、券商拆分、产业事件联动、可信机构/媒体），只标记 `核心定价 / 次要定价 / 期权价值 / 证据不足`，不虚构精确权重。

每项业务回指已完成的产业单元，检查产品功能与直接客户、研发/送样/认证/小批量/批量状态、产能/产量/利用率/良率、收入/毛利/资本开支/现金流和相对行业弹性。合并披露保持“未单列”，不反推分部利润；“可适配”“规划产能”“客户验证”“批量收入”是不同兑现阶段。公司类型（成长、周期、价值、主题、混合）只作描述，不自动生成交易建议。

完成标准：每项重要业务均有产业回指、产品边界、收入/利润/产能/客户兑现状态和证据；收入、利润、市值主线分开。

## 7. A×B｜传导差与错配

逐业务交叉：

| System A | System B | 只回答 |
|---|---|---|
| 景气与驱动力 | 业务暴露 | 是否位于真正受益环节 |
| 拐点与下一确认 | 客户、产能、收入 | 产业变化是否传导到收入 |
| 生命周期与竞争 | 良率、毛利、现金流 | 收入能否转为利润与现金 |
| 行业反证 | 市值定价 | 定价领先、同步还是落后兑现 |

公司级结论必须包含最强产业顺风、最大兑现断点、收入/利润/市值错配、下一验证点和失效条件；保持“产品存在、产品量产、财务兑现、市值定价”四层分离。每条业务有行业事实、公司事实和反证。

## 8. 内容地图与一次有界编辑回路

建立“一个主张一个主叙事归属”的内容地图，并给重要主张分配 `claim_id`。每个区块只承担一项叙事：

| 区块 | 唯一职责 |
|---|---|
| `industry-thesis` | 只给结论；不复制证据组 |
| `chain-map` | 只给产业结构与传导关系 |
| `prosperity-dashboard` / `inflection-dashboard` | 只给 System A 状态、变化、下一确认 |
| `industry-signals` | 只放决定性证据与反证 |
| `system-b` | 只放公司兑现与主线 |
| `combined-conclusion` | 只放 A×B 传导差、错配、验证点 |
| `evidence-ledger` | 承载数字、单位、口径、日期和来源 |
| `risks` | 风险、反证、失效条件与降级表达 |

同一段话或同一组数字不在文字总结与图示中完整复述；用短标签或 `claim_id` 交叉引用即可。必备 ID 保留，但其内部若无新增信息，应删除冗余卡片或把文字并入该区块的唯一职责，不得为了填满版面重复结论。桌面表与移动卡来自同一数据结构，不形成两个事实源。

报告生成固定一次回路：

`证据完整初稿 → 内容归属检查 + 语义重复检查 + 移动端检查 → 最多一次自动精修 → 重跑受影响 gates`

精修只编辑当前报告；不运行时修改本 skill。若重跑仍失败，标记 `unresolved`（写明 gate、证据/节点和下一动作），停止本轮并由使用者决定下一轮；不无限迭代。

反馈分流：证据、边界、去重、移动可读性、来源等 **universal quality** 自动进入 harness；篇幅、视觉偏好、附录深度等 **report preference** 只作用当前报告或等待用户选择；**conflicting feedback** 不自动固化，明确请求用户选择。不得把某一评价者的主观风格硬编码为普遍规则。

## 9. 自包含 HTML 与移动优先

输出 `output/industry/YYYY-MM-DD-股票代码-公司简称.html`，行业分支用 `YYYY-MM-DD-行业简称.html`。内联 CSS 与少量必要 JavaScript，不依赖 CDN、远程字体或框架。设计对象是面向投资研究者的产业传导决策台，单一任务是判断方向及下一确认；使用冷静、精密、材料科学语义，刻意选择字体、4–6 色调和一个签名视觉（双仪表），避免模板化装饰与无意义动画。支持键盘焦点、`prefers-reduced-motion`、打印样式。

桌面决策表最多 5 个有意义列；超过则拆表、卡片或分层。390px 时把决策表、A×B、产业单元比较渲染为纵向卡片或 definition list，不靠小字号多列表格，不让页面横向滚动。证据账本也提供同源移动卡片视图，细节可折叠；表格横滚只能是非主路径 fallback。状态同时使用文字和形状，不只靠颜色。页面不得横向溢出。

所有分支必须包含且每个 ID 只出现一次：`report-header`, `industry-thesis`, `chain-map`, `system-a`, `prosperity-dashboard`, `inflection-dashboard`, `industry-signals`, `risks`, `evidence-ledger`。公司分支额外包含且每个 ID 只出现一次：`system-b`, `valuation-drivers`, `combined-conclusion`。使用语义化 `header/main/section/table/footer`；公开来源直达原文并带 `rel="noopener noreferrer"`；`report-header` 标注 `已有资料 + WEB`、`WEB` 或 `资料不足`；缺失数据写“待补：字段＋首选来源＋时效”；页脚写生成时间、分析时点、报告期和“不构成投资建议”。
